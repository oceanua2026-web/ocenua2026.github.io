# OceanUA — нотатки для розробників / AI-асистентів

Цей файл описує неочевидні особливості структури проєкту, які легко
пропустити при внесенні змін (особливо при додаванні нових предметів
флешкарток). Перед редагуванням `data/flashcards/*.js` прочитайте цей файл.

## 0. Обов'язкові правила перед будь-якими змінами

Це основна інструкція щодо структури програми та створення флешкарток.
Перед роботою прочитайте `AGENTS.md` і цей `README.md` у корені OceanUA.
Назву `README.md` зберігайте: це стандартна точка входу в документацію.

Усі файли програми, інструменти імпорту, дані та зображення зберігайте
в каталозі OceanUA. Папка школи використовується лише як джерело імпорту.

При КОЖНІЙ зміні програми, зокрема карток, зображень, назви або інтерфейсу:

1. Оновіть версію та дату і час у пункті «Про програму» (`app.js`, `about`).
2. Використовуйте фактичний час зміни в часовому поясі `Europe/Kyiv`.
   Формат версії: `YYYY.MM.DD.HHmm`; формат дати й часу: `DD.MM.YYYY о HH:mm`.
   Якщо в цю хвилину вже випущено версію, додайте секунди до версії та часу.
3. Оновіть `?v=` у `index.html` для змінених безпосередньо підключених
   файлів. Для файлів карток оновіть `?v=` у полі `dataFile` каталогу
   `data/grade-flashcards.js`, а потім версію самого каталогу в `index.html`.
   Завжди оновлюйте `?v=` для `app.js`, бо в ньому змінюється версія.
4. Перевірте зміни та за потреби доповніть цю інструкцію новими правилами.

Дата версії є датою внесення змін, а не поточним часом відкриття сторінки.
Завдання не завершене, доки «Про програму» показує попередню версію.

## 1. Додавання нового предмету флешкарток — ДВА обов'язкові кроки

Дані предметів можуть зберігатися у двох сумісних формах:

- старі/невеликі набори: безпосередньо в `data/flashcards/grade-N.js`;
- нові великі набори: в окремих файлах `data/flashcards/grade-N/<subject-id>.js`,
  які самі додають subject у `window.OCEANUA_NMT.years["N клас"].subjects`.

Не складайте всі нові предмети в один монолітний `grade-N.js`: файли
9-11 класів уже важкі, тому для реальних підручникових наборів стандартом є
окремий файл на предмет/пакет у папці відповідного класу.

Але сам факт наявності предмету в будь-якому data-файлі **НЕ означає**, що він з'явиться
в інтерфейсі! Список предметів, які показуються у випадаючому меню
"Предмет, автор, рік" для кожного класу, визначається **окремим каталогом**:

    data/grade-flashcards.js   (window.OCEANUA_GRADE_FLASHCARDS)

Цей каталог має структуру `grades["N"].subjects = [{id, label}, ...]`.
Для кожного класу N там перелічені id предметів, які реально будуть
підвантажені з `grade-N.js` (пошук іде за `subjectConfig.id` в
`nmtData.years[...].subjects[id]`, див. `buildFlashcardGradeData` в `app.js`).

Файли класів і окремих предметів не підключаються безпосередньо в
`index.html`. Їхні шляхи з версіями записуються в каталозі:

```js
"9": {
  dataFile: "data/flashcards/grade-9.js?v=YYYYMMDD-HHMM",
  subjects: [
    {
      id: "algebra_ister_9_2026",
      label: "Алгебра - Істер, 2026",
      dataFile: "data/flashcards/grade-9/algebra-ister-2026.js?v=YYYYMMDD-HHMM"
    }
  ]
}
```

`app.js` завантажує базовий файл класу лише після відкриття карток цього
класу. Поле `subject.dataFile` використовується для винесених пакетів:
такий файл завантажується лише після вибору відповідного предмета.
Повторне підключення того самого файла блокується кешем завантажувача.

**Якщо додали новий subjectId в data-файл, але не додали відповідний
рядок `{id, label}` в `data/grade-flashcards.js` → предмет не з'явиться
в UI, хоча дані коректні.** Саме ця помилка вже траплялась (серпень 2026).

Додатково: `subjectConfig.label` з каталогу **завжди перевизначає**
`subject.label` з даних (пріоритет каталогу). Тобто назва, яку бачить
користувач, береться з `grade-flashcards.js`, а не з `grade-N.js` —
при зміні назви предмету треба оновлювати обидва місця синхронно
(або хоча б каталог, бо саме він відображається).

## 2. Кешування — версійні query-параметри в index.html

`index.html` підключає основні файли з версійним параметром, а шляхи
відкладено завантажуваних карток містяться в `data/grade-flashcards.js`:

    <script src="data/grade-flashcards.js?v=YYYYMMDD-HHMM"></script>
    <script src="app.js?v=YYYYMMDD-HHMM"></script>

**Після КОЖНОЇ зміни відповідного файлу треба бампати ?v= для нього**
(поточна дата/час, формат `YYYYMMDD-HHMM`). Інакше браузер може віддати
закешовану стару версію файлу навіть після перезавантаження сторінки —
користувач бачитиме старі дані попри те, що файл на диску вже оновлений.

## 3. Два формати даних для предметів у grade-10.js

`grade-10.js` історично використовує "плаский" формат (один комплект
"Тренувальний набір" на предмет):

```js
subjectId: {
  label: "Назва предмету",
  cards: [
    [topicLabel, question, [опція1, опція2, опція3, опція4], correctIndex],
    ...
  ]
}
```

Для предметів, замінених на реальні підручникові дані (наприклад
`biology_sobol_10`, `algebra_merzliak_10`, `english_10`,
`world_history_hisem_10`), використовується **інший, "topics"-формат**,
ідентичний до того, що застосовується в `grade-11.js` — кожен §/розділ/юніт
стає ОКРЕМИМ комплектом (variant) з власною назвою замість одного
загального "Тренувального набору":

```js
subjectId: {
  label: "Предмет - Автор, Рік",
  sourceUrl: "...",
  topics: [
    { id: "slug", label: "§ N. Назва параграфа", cards: [[question, [опції], correctIndex], ...] },
    ...
  ]
}
```

Код-білдер у `grade-10.js` (`const subjects = ...`) сам визначає формат
за наявністю `deck.topics` (новий) чи `deck.cards` (старий, flat) і
викликає відповідно `makeTopicCards` або `makeCards`. **Не змішуйте
`cards` і `topics` в одному об'єкті предмету** — має бути присутнє
рівно одне з двох полів.

`grade-11.js` використовує ЛИШЕ topics-формат, без flat-варіанту.

## 4. Формат картки (4-й елемент)

- `grade-11.js` topics-формат: `[question, [4 опції], correctIndex, explanationText]`
  (4 елементи — є текстове пояснення).
- `grade-10.js` topics-формат: `[question, [4 опції], correctIndex]`
  (3 елементи — пояснення немає).
- `grade-10.js` flat-формат (старі предмети): `[topicLabel, question, [4 опції], correctIndex]`
  (topic йде першим елементом, бо всі картки предмету в одному комплекті).

## 4.1. Нова рекомендована структура карток з медіа

Для нових реальних підручникових наборів, особливо коли потрібні рисунки,
використовуйте topics-формат і об'єкт картки замість масиву:

```js
{
  question: "Текст запитання",
  options: ["Правильна відповідь", "Хибний варіант 1", "Хибний варіант 2", "Хибний варіант 3"],
  correctIndex: 0,
  answer: "Повна відповідь або пояснення",
  image: "assets/flashcards/grade-9/algebra-ister-2026/example.png",
  imageAlt: "Опис рисунка",
  imageCaption: "Необов'язковий підпис"
}
```

`image`, `imageAlt` і `imageCaption` необов'язкові. Зображення зберігайте
всередині `assets/flashcards/grade-N/<subject-id>/`. Рендерер `app.js`
показує поле `image` під запитанням. Sanitizer дозволяє тільки локальні
PNG-шляхи виду `assets/.../*.png`; зовнішні зображення не пропускаються.

Кожна картка має запитання, рівно чотири різні варіанти та лише одну
правильну відповідь. `correctIndex` — індекс правильної опції від 0 до 3;
її позицію слід чергувати. Неправильні варіанти не мають бути іншими
правильними формулюваннями відповіді на це саме запитання.
Білдер перетворює об'єкт на `type: "single"`, `questionHtml`,
`options: [{key: "А", text: "..."}, ...]`, `correctKey` (літера А/Б/В/Г)
та `answerText` з поля `answer`. `shortAnswer` у джерелі імпорту — це
текст правильної опції, а не значення `correctKey` готової картки.
Після вибору будь-якої опції інтерфейс одразу підсвічує правильну зеленим,
помилково вибрану — червоним, і показує розгорнуту відповідь унизу.
Не створюйте `type: "input"` для цих підручникових наборів.

Для рисунка до пояснення додайте `imagePlacement: "answer"`: він з'явиться
внизу лише після відповіді. Без цього поля рисунок показується під запитанням.
PNG зберігаються окремими файлами; до JavaScript входить лише відносний шлях.

## 5. Обробка вихідних текстових архівів підручників (*.txt → флешкартки)

При генерації нових карток з архівів реальних підручників:

- Завжди перевіряйте архів на **дублікати файлів** (повні або майже
  повні співпадіння секцій) до обробки — таке вже траплялось кілька
  разів (напр. Зарубіжна література 11 кл, Біологія 11 кл, Всесвітня
  історія 10 кл). Дублікат виключається з обробки повністю.
- Практичні завдання без фактичної відповіді ("намалюйте карту",
  "напишіть лист", "індивідуальне завдання") виключаються з набору
  карток — вони не придатні для формату "питання + 4 варіанти".
- Питання завжди беруться дослівно з підручника; варіанти відповіді —
  або реальні відповіді на інші питання того ж параграфа (1 правильна +
  3 дистрактори), залежно від типу джерела.

## 6. Каталог у data/grade-flashcards.js — не єдине джерело правди

`sourceYears` в конфігурації предмету каталогу визначає, з яких
"років" (ключів `nmtData.years[...]`, напр. `"10 клас"`, `"11 клас"`)
підтягуються variants для цього предмету. Якщо не вказано явно,
береться `config.sourceYears` класу або дефолтний список усіх років —
перевіряйте це поле, якщо предмет повинен об'єднувати дані з кількох
років.

## 7. Статистика та оцінювання (версія 2)

Кожна сесія зберігає правильні, неправильні й невідповідані питання,
відсоток виконання та `grade12`. Формула: `ceil(12 * correctCount / total)`,
мінімум 1 і максимум 12. Поки немає жодної відповіді, оцінка відсутня.
Знаменник — усі доступні питання вибраного комплекту, а не лише відповіді.
До завершення оцінка позначається попередньою. Перегляд відповіді без
власного вибору рахується як неправильна відповідь. Повторна відповідь
на те саме питання в сесії не додає результат; нова спроба створює нову сесію.

Оцінку видно у поточному тесті, списку сесій, деталях та JSON-експорті.
Середня оцінка враховує лише завершені сесії й показується з одним десятковим
знаком. Стара історія сумісна: лічильники й оцінки обчислюються з масиву
відповідей при читанні, без зміни часу завершення. Чистий перезапуск не має оцінки.

Картка може мати масив `media` для кількох рисунків. Без `media` працює
попереднє поле `image`. Для кожного рисунка `imagePlacement: "answer"`
відкладає показ до відповіді, решта зображень показуються біля запитання.

будинку та дубль педколеджу в переліку ЗЗСО не включені як окремі школи.
Не визначайте форму власності за суперечливими записами довідників.
При оновленні перевіряйте джерела, дату та версію підключення в `index.html`.
Вибір населеного пункту під час налаштування профілю обробляється раніше
та відкриває список закладів для заповнення профілю.

Натискання на назву будь-якого закладу відкриває карту міста. Посилання
на джерела та офіційні сайти залишаються окремими зовнішніми посиланнями.


## 9. Клас / група та файл для вчителя

Профіль містить `groupName` (наприклад, 9-А або 121) окремо від `grade`.
Список закладів міста в налаштуваннях включає школи й коледжі з довідника;
коди мають префікси `isuo:` / `edbo:`, щоб не змішувати різні реєстри.
Кожна нова тестова сесія фіксує `schoolName`, `schoolCode`, `grade`,
`groupName`, місто та учня на момент запуску. Подальша зміна профілю не
переписує історію. Старі результати без групи автоматично не приписуються
до поточної групи: їхню попередню належність неможливо достовірно відновити.
JSON-експорт має `schemaVersion: 3` і профіль. У статистиці можна завантажити
декілька JSON-файлів учнів та вивантажити вибрану групу у UTF-8 CSV із BOM
і роздільником `;` для Excel. Групи розділяються за містом, закладом,
класом і назвою групи; повторні сесії з однаковими userKey/id не дублюються.
Імпорт не змінює локальні профілі та особисту статистику; тримається в
пам'яті до перезавантаження. Звіт включає завершені й незавершені спроби
та позначає попередні оцінки. Реєстрація і статистика локальні для браузера;
спільної бази результатів різних пристроїв наразі немає.


### 9.1. Поля та зв'язки даних

| Об'єкт | Поля | Призначення |
| --- | --- | --- |
| Довідник міста | ключ — код КАТОТТГ; `name`, `checkedAt`, `mapTarget`, `schools`, `colleges` | Прив'язка списку закладів до міста та його карти |
| Заклад довідника | `id`, `name`, `address`, `type`, `sources` | Назва, адреса, тип та джерела перевірки |
| Джерело | `label`, `url` | Окреме зовнішнє посилання на реєстр або сайт |
| Профіль | `placeCode`, `placeName`, `schoolName`, `schoolCode`, `schoolAddress`, `schoolPlaceCode`, `grade`, `groupName` | Поточне місто, заклад, номер класу та повна назва класу / групи |
| Зареєстрований користувач | `id`, `name`, `placeCode`, `city`, `schoolName`, `schoolCode`, `grade`, `groupName` | Поточна навчальна належність користувача; також зберігаються наявні контакти й роль |
| Тестова сесія | `id`, `userKey`, `userName`, `placeCode`, `placeName`, `schoolName`, `schoolCode`, `grade`, `groupName` | Незмінний знімок навчальної належності на момент запуску тесту |
| Результат сесії | `total`, `answeredCount`, `correctCount`, `wrongCount`, `unansweredCount`, `grade12`, `scorePercent`, `scoreVersion`, `answers`, `status` | Відповіді, оцінювання та стан спроби |

`grade` — номер шкільного класу (1–12), `groupName` — текстова назва
класу / групи (9-А, 9-Б, 121, 122). Номер групи коледжу зберігається
рядком, а не числом; `grade` для коледжу можна залишити порожнім.
Коди закладів довідника в профілі й статистиці мають вигляд `isuo:16684`
або `edbo:403`. Назви потрібні для відображення, коди — для розрізнення.
Для закладів з раніше підключених карт зберігаються їхні наявні коди.

### 9.2. Поведінка налаштувань та історії

Поля «Місто» та «Назва навчального закладу» відкривають спільний вибір
через меню «Місто». Окрема кнопка вибору міста та випадаючий список
закладів у налаштуваннях прибрані. Після вибору міста відкривається список
його закладів; вибір школи / коледжу заповнює обидва поля й повертає
користувача до налаштувань. Якщо список закладів ще не підключено,
зберігається лише місто з поясненням.
Вибір закладу заповнює його назву, код, адресу й код міста; введені дані
форми зберігаються. Назва закладу у налаштуваннях доступна лише для вибору через довідник.
Зміна закладу очищає назву попередньої групи.
Зміна вже вибраного міста очищає попередній заклад і назву групи.
Поле групи зберігається у локальній реєстрації після збереження профілю.

Зміна поточної групи учня не змінює вже створені тестові сесії. Старі
сесії без цих полів залишаються в особистій історії, але не потрапляють
до звіту групи без достовірно збереженої назви закладу та групи.

### 9.3. Формати обміну та звіт учителя

Особистий JSON-файл містить `exportedAt`, `schemaVersion: 3`, `userKey`,
`profile`, `sessions`. Версія JSON-файлу незалежна від `scoreVersion: 2`,
яка позначає чинний механізм оцінювання. `profile` містить збережений
профіль, включно з контактами; це потрібно враховувати при обміні файлами.

У розділі «Статистика» учитель може вибрати декілька JSON-файлів одразу.
Некоректні файли позначаються повідомленням, коректні обробляються.
Завантажені сесії об'єднуються з локальними лише для групового звіту;
особистий список результатів та зареєстровані користувачі не змінюються.
Повторні записи відсіюються за парою `userKey` та `id` сесії.

Ключ групування: місто (код або назва), заклад (код або нормалізована
назва), `grade`, нормалізована `groupName`. Однаково названі групи різних
закладів не об'єднуються. Для узгоджених звітів учні мають вибирати той
самий заклад зі списку та однаково записувати назву групи, наприклад 9-А.

CSV-файл містить по одному рядку на тестову спробу: учень, ідентифікатор
учня, місто і його код, заклад і його код, клас, назва класу / групи,
предмет, комплект тесту, час початку та завершення, статус, кількість
питань, правильні, неправильні й невідповідані, оцінка / 12 та її тип.
Це звіт за спробами, а не автоматичний вибір найкращої оцінки учня.
Перед експортом оцінки перераховуються чинною формулою з розділу 7.
Текстові значення, які Excel міг би сприйняти як формулу, екрануються.

### 9.4. Майбутня хмарна реєстрація — вимоги до інтеграції

Сервер та спільна база наразі не підключені. При перенесенні в хмару
потрібно зберегти описані поля профілю, користувача та знімка сесії.
Сервер має пов'язувати результат зі стабільним ідентифікатором учня;
поточний локальний `userKey` необхідно узгодити із серверною реєстрацією.

Для вибору групи бажано мати окремий стабільний серверний ідентифікатор
групи та зв'язок учень → група → заклад → місто. Назва групи залишається
відображуваним полем. Такий ідентифікатор поки не реалізований: поточне
групування використовує описаний вище складений ключ.

Учитель зможе отримувати результати учнів групи з серверної бази після
реалізації серверного збереження сесій і перевірки доступу вчителя до
відповідного закладу / групи. Сам список зареєстрованих учнів не містить
їхніх відповідей та оцінок і не замінює базу тестових результатів.
При серверній інтеграції збережіть історичну групу сесії, сумісність
JSON-експорту та можливість отримати один файл статистики групи.

У звичайному меню натискання на заклад відкриває карту. У режимі вибору
з налаштувань воно зберігає заклад у профілі й повертає до налаштувань.
Обидва поля відкривають повне дерево місць зі збереженою поточною гілкою.


### 9.5. Єдиний розділ «Профіль»

Пункт «Налаштування» прибрано з головного меню. Усі його поля знаходяться
у формі «Реєстрація і редагування профілю», доступній з пункту «Профіль»
та кнопки профілю у верхній панелі. Пункт «Вихід з профілю» замінено
пунктом «Профіль» із двома діями: гостьовий режим та реєстрація / редагування.
Кнопка «Залишитися у профілі» замінена на «Реєстрація і редагування профілю».
У гостя верхня кнопка відображає «Гість». Вибір гостьового режиму очищає
активний профіль і показує «Гість», не відкриваючи форму налаштувань;
існуючі зареєстровані користувачі та історія результатів залишаються.
Внутрішній розділ форми — `profile-edit`, головна сторінка — `profile`.
Повернення після вибору міста / закладу веде у форму редагування профілю.
Згадки «налаштувань» у попередніх розділах описують поля цієї форми.

Пункт «Про програму» розташований останнім у головному меню, після «Профіль».
