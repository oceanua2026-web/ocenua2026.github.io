# OceanUA — нотатки для розробників / AI-асистентів

Цей файл описує неочевидні особливості структури проєкту, які легко
пропустити при внесенні змін (особливо при додаванні нових предметів
флешкарток). Перед редагуванням `data/flashcards/*.js` прочитайте цей файл.

## 1. Додавання нового предмету флешкарток — ДВА обов'язкові кроки

Дані одного предмету (масив карток) зберігаються в `data/flashcards/grade-N.js`.
Але сам факт наявності предмету в цьому файлі **НЕ означає**, що він з'явиться
в інтерфейсі! Список предметів, які показуються у випадаючому меню
"Предмет, автор, рік" для кожного класу, визначається **окремим каталогом**:

    data/grade-flashcards.js   (window.OCEANUA_GRADE_FLASHCARDS)

Цей каталог має структуру `grades["N"].subjects = [{id, label}, ...]`.
Для кожного класу N там перелічені id предметів, які реально будуть
підвантажені з `grade-N.js` (пошук іде за `subjectConfig.id` в
`nmtData.years[...].subjects[id]`, див. `buildFlashcardGradeData` в `app.js`).

**Якщо додали новий subjectId в `grade-N.js`, але не додали відповідний
рядок `{id, label}` в `data/grade-flashcards.js` → предмет не з'явиться
в UI, хоча дані коректні.** Саме ця помилка вже траплялась (серпень 2026).

Додатково: `subjectConfig.label` з каталогу **завжди перевизначає**
`subject.label` з даних (пріоритет каталогу). Тобто назва, яку бачить
користувач, береться з `grade-flashcards.js`, а не з `grade-N.js` —
при зміні назви предмету треба оновлювати обидва місця синхронно
(або хоча б каталог, бо саме він відображається).

## 2. Кешування — версійні query-параметри в index.html

`index.html` підключає дата-файли з версійним параметром:

    <script src="data/flashcards/grade-10.js?v=YYYYMMDD-HHMM"></script>
    <script src="data/flashcards/grade-11.js?v=YYYYMMDD-HHMM"></script>
    <script src="data/grade-flashcards.js?v=YYYYMMDD-HHMM"></script>
    <script src="app.js?v=YYYYMMDD-HHMM"></script>

**Після КОЖНОЇ зміни відповідного файлу треба бампати ?v= для нього**
(поточна дата/час, формат `YYYYMMDD-HHMM`). Інакше браузер може віддати
закешовану стару версію файлу навіть після перезавантаження сторінки —
користувач бачитиме старі дані попри те, що файл на диску вже оновлений.

## 3. Два формати даних для предметів у grade-10.js

`grade-10.js` історично використовує "плаский" формат (один комплект
"Тренувальний набір" на предмет):

```js
subjectId: {
  label: "Назва предмету",
  cards: [
    [topicLabel, question, [опція1, опція2, опція3, опція4], correctIndex],
    ...
  ]
}
```

Для предметів, замінених на реальні підручникові дані (наприклад
`biology_sobol_10`, `algebra_merzliak_10`, `english_10`,
`world_history_hisem_10`), використовується **інший, "topics"-формат**,
ідентичний до того, що застосовується в `grade-11.js` — кожен §/розділ/юніт
стає ОКРЕМИМ комплектом (variant) з власною назвою замість одного
загального "Тренувального набору":

```js
subjectId: {
  label: "Предмет - Автор, Рік",
  sourceUrl: "...",
  topics: [
    { id: "slug", label: "§ N. Назва параграфа", cards: [[question, [опції], correctIndex], ...] },
    ...
  ]
}
```

Код-білдер у `grade-10.js` (`const subjects = ...`) сам визначає формат
за наявністю `deck.topics` (новий) чи `deck.cards` (старий, flat) і
викликає відповідно `makeTopicCards` або `makeCards`. **Не змішуйте
`cards` і `topics` в одному об'єкті предмету** — має бути присутнє
рівно одне з двох полів.

`grade-11.js` використовує ЛИШЕ topics-формат, без flat-варіанту.

## 4. Формат картки (4-й елемент)

- `grade-11.js` topics-формат: `[question, [4 опції], correctIndex, explanationText]`
  (4 елементи — є текстове пояснення).
- `grade-10.js` topics-формат: `[question, [4 опції], correctIndex]`
  (3 елементи — пояснення немає).
- `grade-10.js` flat-формат (старі предмети): `[topicLabel, question, [4 опції], correctIndex]`
  (topic йде першим елементом, бо всі картки предмету в одному комплекті).

## 5. Обробка вихідних текстових архівів підручників (*.txt → флешкартки)

При генерації нових карток з архівів реальних підручників:

- Завжди перевіряйте архів на **дублікати файлів** (повні або майже
  повні співпадіння секцій) до обробки — таке вже траплялось кілька
  разів (напр. Зарубіжна література 11 кл, Біологія 11 кл, Всесвітня
  історія 10 кл). Дублікат виключається з обробки повністю.
- Практичні завдання без фактичної відповіді ("намалюйте карту",
  "напишіть лист", "індивідуальне завдання") виключаються з набору
  карток — вони не придатні для формату "питання + 4 варіанти".
- Питання завжди беруться дослівно з підручника; варіанти відповіді —
  або реальні відповіді на інші питання того ж параграфа (1 правильна +
  3 дистрактори), залежно від типу джерела.

## 6. Каталог у data/grade-flashcards.js — не єдине джерело правди

`sourceYears` в конфігурації предмету каталогу визначає, з яких
"років" (ключів `nmtData.years[...]`, напр. `"10 клас"`, `"11 клас"`)
підтягуються variants для цього предмету. Якщо не вказано явно,
береться `config.sourceYears` класу або дефолтний список усіх років —
перевіряйте це поле, якщо предмет повинен об'єднувати дані з кількох
років.
